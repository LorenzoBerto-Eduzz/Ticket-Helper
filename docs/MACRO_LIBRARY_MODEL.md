# TicketHelper Macro Library

This is the original TicketHelper macro library, released in v2.1.0 and separate from the older ProKeys-triggered MacroActions in `docs/MACRO_AUTOFILL_MODEL.md`. No ProKeys code is copied.

## Owner decisions

- The **Macros** card appears below keyboard shortcuts. Its first row is **Expandir Macro**, an internal, directly editable shortcut that defaults to `Shift+Space`. It is not a `chrome.commands` shortcut. The main TicketHelper enabled switch controls expansion. There is no separate macro switch and no automatic ProKeys coexistence handling. The owner will manage ProKeys during testing.
- Type an abbreviation immediately before the caret, bounded by a space or line break, then press the configured shortcut. Matching ignores case; without a match, the key retains normal browser behavior. A match replaces only that abbreviation, adds no extra space, and then runs existing MacroActions on the inserted content. An unavailable MacroAction leaves its `XX...XX` label visible. Expansion also works in TicketHelper's own macro body editor. Creating a macro from highlighted page text and macro suggestions are later features.
- Rich editors receive formatted text and images where they accept them. Discord's Slate editor uses a Discord-only main-world adapter to replace an abbreviation in the editor's own message model. The adapter verifies the focused editor and exact abbreviation at the model caret before editing. If it cannot find that editor, it leaves the abbreviation intact; it never inserts a detached DOM span that looks visible but cannot be deleted or sent. Discord receives plain text with line breaks and skips images. Multiline plain fields receive text and line breaks. Single-line fields receive text with newlines converted to spaces. Plain fields skip images. Password and other nontext inputs are excluded. Chrome internal pages are outside ordinary extension content-script reach. Third-party editors may filter formatting; live checks are required for each important site. HubSpot's existing rich insertion path, including images, remains separate from Discord's Slate path.
- The Macros list is in permanent, increasing ID order. It displays up to eight compact closed rows before its own vertical scroll; the transparent scrollbar sits in the right card margin. Opening a macro adds that editor's full height and extra spacing to the scroll area's limit, and a ResizeObserver follows content growth. Each full-width abbreviation row toggles one expanded editor; clicking directly on a closed abbreviation also focuses its field and selects all its text; only clicking its row or opening another macro collapses it; clicks and focus changes elsewhere leave it open. The same abbreviation textarea remains visible in closed and open modes, with identical text position; closed mode is read-only and transparent, open mode shows its border/background and accepts edits. A pencil appears only while hovering a closed row; an open row shows a subdued checkmark that turns white when hovering the area to the right of its abbreviation. The abbreviation field sizes to its text with the same 7px horizontal inset as MacroAction labels, wraps if needed, and caps at 50 characters. Clearing it on blur deletes that macro. The full-width editor has a small initial one-line writing area, a dark grouped formatting toolbar with conventional icons, straight divider, white sans-serif writing area, rounded outer corners, and no internal scroll bar. Text color starts black; background highlight starts empty. The ordered and bullet list buttons manipulate editor list nodes directly and saved HTML retains lists; expansion into inline rich editors uses visible numbered or bullet lines. `+ Adicionar Macro` opens an editable draft. A draft requires an abbreviation and content before it is saved. Edits save on input, blur, collapse, Options window blur/visibility loss, and pagehide; concurrent input saves coalesce to avoid a long write queue. The entire add row is clickable without widening the visible button; the same applies to the add rows for MacroActions and producer notices.
- **Expandir Macro** is the last keyboard-shortcut row. It is internal, defaults to `Shift+Space`, and shows that combination as a suggestion if changed; Chrome's extension-shortcuts page does not list it. The Options shortcuts list starts collapsed to its first three action rows plus a centered arrow row. Hovering anywhere in that compact area brightens the arrow; clicking anywhere expands all action rows for the current Options page session. A shortcut fired on Options also expands the list before highlighting its action row.
- Duplicate abbreviations, ignoring case, are allowed as saved records. The lowest ID with content is active. Later matches stay editable but inactive and show a red warning that identifies the active ID; clicking the warning opens it. Removing or renaming the active one promotes the next ID.
- Import replaces the entire macro library only after a count confirmation. TicketHelper's versioned `.json` export contains every macro plus base64 image data in one portable file. ProKeys 4.0.2's full-settings or snippets-only JSON export is accepted for one-time migration: recursively flatten folders, take each `name` as abbreviation and `body` as rich HTML or plain text, assign increasing IDs in file order, and ignore unrelated settings. ProKeys-only dynamic `[[%...]]` commands are left as text and counted in the import confirmation. CSV is not the rich migration format. An invalid file or missing image fails before replacing saved macros. The export is needed as a backup before extension removal.

## Implementation map

- The collapsed shortcut list places its expand arrow after the third visible action. The macro-list thumb uses the same subdued color as the transfer icons, centered in the right card margin without arrow buttons or an opaque track. A one-row fade appears only in directions with more scrollable content: never above the first row or below the last row, and never over the scrollbar; the open editor has extra vertical separation. The scrollbar thumb has equal space between the editor edge and the card edge.
- Opening or closing a macro adjusts the list's scroll offset so the clicked abbreviation remains visible at its prior position when possible. Opening another macro anchors the newly clicked abbreviation. All three editable lists have no internal height cap, scrollbar thumb, or directional fade when at most eight rows are visible, including after a search filter. The ninth visible row enables scrolling and directional fades. Wheel movement over a scrollable list or its viewport margin stays within that list instead of moving the Options page. The MacroActions and Producer Notices lists reserve the scrollbar gutter; the MacroActions choice menu uses viewport positioning so scrolling cannot clip it.
- Options has a visual-only search for Macros, MacroActions, and Producer Notices beside each section's import/export icons. The monospaced search field appears on hover/focus and grows left toward the title. Enter, icon click, or leaving the field applies a case- and accent-insensitive substring filter to the key and visible text; typing alone does not change rows. Clearing the field and leaving it restores all rows. The icon also focuses the field for typing. The filter never changes stored records, imports, or exports. Adding a new item clears that section's visual filter. `project/search_filter_core.js` keeps matching independent of the Options UI for possible later reuse; no ticket-page macro picker is implemented yet.

- `project/macro_library_core.js`: shortcut normalization, ProKeys JSON parser, duplicate/ID index.
- `project/macro_library_store.js`: IndexedDB macros, image blobs, ID sequence, atomic full replacement. This avoids `chrome.storage.sync` quotas and avoids re-encoding images on each live lookup.
- New IDs are allocated inside the same IndexedDB write transaction as the macro, so simultaneous Options windows cannot claim the same ID. Removing an abbreviation deletes that record; imported replacements validate before replacing the whole store.
- `project/macro_library_html.js`: allowed rich HTML, plain-text conversion, ProKeys/plain content handling. Treat imported HTML as untrusted; scripts, event handlers, and unsupported URLs must never be executed.
- The rich editor may emit a literal newline inside a paragraph (especially with Shift+Enter). Normalize it into an explicit `<br>` immediately on input, preserving the caret, and also convert existing/imported literal newlines during sanitization. Otherwise the editor's `white-space: pre-wrap` shows a new line that HubSpot collapses into a space when the macro expands. Empty paragraphs and repeated `<br>` nodes must retain their visible blank lines.
- `project/macro_library_options.js`: card rows, inline key capture, native rich editor controls, autosave, image paste, single-file import/export. Image bytes are separate in IndexedDB and embedded only in exported JSON. Existing `project/options.js` key-capture validation accepts only letters/digits; the macro shortcut has its own Space-capable capture module.
- `project/macro_library_background.js`: returns the active abbreviation index and requested macro to content scripts; storage revision broadcasts updates to open tabs. Text bodies are cached per page; image bytes are requested only on a matching expansion.
- Change notifications use an increasing revision, including when two edits occur within one millisecond. Plain-text conversion keeps one blank line as one newline gap between paragraphs.
- `project/macro_library_expander.js`: lightweight keydown listener on HTTP(S) pages and the Options page. It inspects the word only on the configured shortcut, checks the caret/field again before an asynchronous image insertion, and inserts rich or plain content as the destination permits. Text macros cache prepared rich/plain representations after first use; rich insertion sanitizes once, and plain conversion runs only for plain fields. Its inserted marker triggers `project/macro_autofill.js` immediately via the input event, while MacroActions still resolve ticket-owned values through the guarded background path. Image bytes remain requested only on a matching expansion.
- `project/discord_slate_adapter.js`: Discord-only main-world bridge for Slate model insertion. The isolated expander requests an insertion through a cancelable event. The adapter finds the focused Slate editor through its React tree, checks the abbreviation in the current model leaf, deletes it through editor operations, and inserts plain text through the editor's data handler. A failed lookup does not fall back to DOM-only insertion. The owner confirmed macro expansion works in Discord; recheck after Discord editor updates.
- The Options rich editor now extends slightly into the card side margins, has more internal top/side padding, black as its default text color, and larger/clearer toolbar color and list controls. Font-size choices put **Pequeno** before the default **Normal**.

## Verification and limits

- `tests/macro_library_core.test.js` covers shortcut normalization, ProKeys structure, duplicate precedence, and invalid exports. `tests/discord_slate_adapter.test.js` checks model insertion and mismatch refusal. Run `node --test tests/*.test.js`, JS syntax checks, manifest JSON parsing, and `git diff --check`. The v2.1.1 suite has 102 passing tests.
- The owner confirmed that an expanded macro now works in Discord. Further live Chrome checks remain useful: styled macro in HubSpot, split `XX...XX` tag across styled spans, image paste/edit/export/import/expand, plain textarea and single-line input, duplicate promotion, options-editor expansion, shortcut change across open tabs, and full ProKeys JSON import. Chrome/site reserved shortcuts and third-party editor sanitization can prevent a chosen combination or formatting from reaching the page; do not claim universal site compatibility without a live check.
